## 📋 Минимальный сценарий проверки

### **Тест 1: Определение типа по содержимому (критический)**

**Цель:** Проверить, что тип определяется по содержимому, даже если имя файла не соответствует.

**Шаги:**
1. Переименуйте файл с данными об электроэнергии: `my_custom_name.xlsx`
2. Загрузите файл через веб-интерфейс или API
3. Проверьте логи сервера

**Ожидаемый результат:**
```log
INFO: Тип ресурса определен после парсинга для my_custom_name.xlsx: electricity (пользователь указал: не указан)
INFO: Определен тип ресурса по содержимому: electricity (счет: X) для файла my_custom_name.xlsx
```

**Проверка в ответе API:**
```json
{
  "resource_type": "electricity",
  "resource_type_label": "Электроэнергия",
  "parsing_status": "success"
}
```

---

### **Тест 2: Несоответствие имени и содержимого**

**Цель:** Проверить, что при несоответствии имени и содержимого используется содержимое.

**Шаги:**
1. Возьмите файл с данными об электроэнергии
2. Переименуйте его в `gaz.xlsx` (имя указывает на газ)
3. Загрузите файл
4. Проверьте логи

**Ожидаемый результат:**
```log
WARNING: ⚠️ Несоответствие типа: пользователь указал 'gas', но содержимое указывает на 'electricity' для файла gaz.xlsx. Используется тип из содержимого.
INFO: Тип ресурса определен после парсинга для gaz.xlsx: electricity (пользователь указал: не указан)
```

**Проверка:**
- В БД сохранен `resource_type = "electricity"` (не "gas")

---

### **Тест 3: Определение по единицам измерения**

**Цель:** Проверить, что единицы измерения (кВт·ч, м³, Гкал) правильно определяют тип.

**Шаги:**
1. Создайте файл с заголовками, содержащими единицы измерения:
   - Тест 3a: Файл с "кВт·ч" → должен быть `electricity`
   - Тест 3b: Файл с "м³" → должен быть `gas` или `water`
   - Тест 3c: Файл с "Гкал" → должен быть `heat`

**Ожидаемый результат:**
- Каждый файл определяется по единицам измерения
- Логи показывают: "Найдены единицы измерения 'кВт·ч' для ресурса 'electricity': X совпадений"

---

### **Тест 4: Определение по структуре данных**

**Цель:** Проверить определение типа по структуре (оборудование, узлы учета, теплопотери).

**Шаги:**
1. Загрузите файл `oborudovanie.xlsx` (оборудование)
2. Загрузите файл `schetchiki.xlsx` (узлы учета)
3. Загрузите файл `ograjdayuschie_konstrukcii.xlsx` (теплопотери)

**Ожидаемый результат:**
- Оборудование → `equipment`
- Узлы учета → `nodes`
- Теплопотери → `envelope`

---

### **Тест 5: Валидация типа пользователя**

**Цель:** Проверить валидацию типа, указанного пользователем.

**Шаги:**
1. Загрузите файл с данными об электроэнергии
2. Укажите тип ресурса: `gas` (неверный тип)
3. Проверьте логи и результат

**Ожидаемый результат:**
```log
WARNING: ⚠️ Несоответствие типа: пользователь указал 'gas', но содержимое указывает на 'electricity' для файла file.xlsx. Используется тип из содержимого.
INFO: Тип ресурса определен после парсинга для file.xlsx: electricity (пользователь указал: gas)
```

## 🔧 Команды для запуска тестов

### **1. Запуск сервиса**

```bash
cd eaip_full_skeleton/services/ingest
uvicorn main:app --reload --port 8001
```

### **2. Загрузка файла через API**

```bash
# Тест 1: Файл с несоответствующим именем
curl -X POST "http://localhost:8001/web/upload" \
  -F "file=@data/source_files/audit_sinergys/pererashod.xlsx" \
  -F "enterprise_name=Тестовое предприятие"

# Тест 2: Файл с несоответствующим именем (переименованный)
# Сначала переименуйте файл: mv pererashod.xlsx gaz.xlsx
curl -X POST "http://localhost:8001/web/upload" \
  -F "file=@gaz.xlsx" \
  -F "enterprise_name=Тестовое предприятие"

# Тест 5: С указанием неверного типа
curl -X POST "http://localhost:8001/web/upload" \
  -F "file=@pererashod.xlsx" \
  -F "enterprise_name=Тестовое предприятие" \
  -F "resource_type=gas"
```

### **3. Проверка логов**

```bash
# Просмотр логов в реальном времени
tail -f logs/ingest.log | grep -i "тип ресурса\|resource_type\|классификатор"

# Или через docker logs (если используется Docker)
docker compose logs ingest | grep -i "тип ресурса\|resource_type"
```

### **4. Проверка в БД**

```bash
# Подключение к SQLite
sqlite3 ingest_data.db

# Проверка сохраненного типа ресурса
SELECT batch_id, filename, resource_type 
FROM uploads 
WHERE filename LIKE '%pererashod%' OR filename LIKE '%gaz%'
ORDER BY created_at DESC 
LIMIT 5;
```

## 🐛 Известные ограничения

1. **Анализ содержимого работает только для Excel и PDF:**
   - Для других форматов используется только анализ имени файла

2. **Минимальный порог уверенности = 2:**
   - Если счет меньше 2, тип не определяется
   - Можно настроить в `content_analyzer.py`

3. **Анализ первых 15 строк:**
   - Для очень больших файлов может не хватить
   - Можно увеличить в `_analyze_excel_content()`
