### 1.2 Выявление разрывов в потоке данных

#### **Критические разрывы:**

1. **Разрыв между загрузкой и парсингом:**
   - ❌ При загрузке файла (`main.py:676-688`) определение типа происходит **ДО парсинга**
   - ❌ `get_resource_with_content_analysis(filename, None)` вызывается с `raw_json=None`
   - ❌ Анализ содержимого невозможен, используется только анализ имени файла
   - ✅ **Решение:** Перенести определение типа ресурса **ПОСЛЕ** парсинга

2. **Разрыв между парсингом и агрегацией:**
   - ⚠️ `energy_aggregator.py:108-119` определяет тип ресурса **только по имени файла**
   - ⚠️ Если файл переименован, агрегация не сработает
   - ✅ **Решение:** Использовать анализ содержимого для определения типа

3. **Разрыв между определением типа и специализированным парсингом:**
   - ⚠️ Специализированные парсеры (`is_equipment_file`, `is_envelope_file`, `is_nodes_file`) проверяют только имя файла
   - ⚠️ Нет проверки содержимого перед специализированным парсингом
   - ✅ **Решение:** Добавить проверку содержимого в специализированные парсеры

### 1.3 Оценка модуля загрузки файлов и его ограничений

#### **Текущая реализация (`main.py:659-688`):**

```python
# Если тип ресурса не указан, пробуем определить автоматически
if not resource_type or resource_type not in RESOURCE_LABELS:
    # Пробуем определить по имени файла
    from utils.content_analyzer import get_resource_with_content_analysis
    safe_filename = os.path.basename(file.filename) if file.filename else ""
    detected_type = get_resource_with_content_analysis(safe_filename, None)  # ❌ raw_json=None
    if detected_type and detected_type in RESOURCE_LABELS:
        resource_type = detected_type
    else:
        resource_type = "other"  # ❌ Fallback на "other"
```

#### **Ограничения:**

1. **❌ Нет анализа содержимого при загрузке:**
   - Файл еще не распарсен, `raw_json=None`
   - Анализ содержимого невозможен
   - Используется только анализ имени файла

2. **❌ Нет повторного определения после парсинга:**
   - После парсинга файла тип ресурса не переопределяется
   - Если имя файла не соответствует содержимому, тип остается неверным

3. **❌ Fallback на "other":**
   - Неопределенные файлы помечаются как "other"
   - Нет попытки определить тип после парсинга

4. **❌ Нет валидации соответствия типа и содержимого:**
   - Если пользователь указал тип вручную, он не проверяется на соответствие содержимому

### 2.1 Как сейчас реализовано определение типов файлов

#### **Уровень 1: Определение по имени файла**

**Файл:** `config/required_data_matrix.py`

```python

    """Определяет тип ресурса по имени файла."""
    for category, resources in REQUIRED_DATA_MATRIX.items():
        for resource_name, resource_config in resources.items():
            if matches_file_pattern(filename, resource_config):

    return ""
```

**Проблемы:**
- ❌ Зависит только от имени файла
- ❌ Не работает при переименовании файлов
- ❌ Нет проверки содержимого

#### **Уровень 2: Анализ содержимого (частично реализован)**

**Файл:** `utils/content_analyzer.py`

```python
def get_resource_with_content_analysis(
    filename: str,
    raw_json: Optional[Dict[str, Any]] = None
) -> str:
    """Определяет тип ресурса, анализируя как название файла, так и его содержимое."""
    # Сначала пробуем определить по названию
    resource_by_name = get_resource_for_file(filename)
    
    # Если не определили по названию и есть содержимое - анализируем содержимое
    if not resource_by_name and raw_json:
        resource_by_content = analyze_file_content(raw_json, filename)
        if resource_by_content:
            return resource_by_content
    
    # Если определили по названию, но есть содержимое - проверяем согласованность
    if resource_by_name and raw_json:
        resource_by_content = analyze_file_content(raw_json, filename)
        if resource_by_content and resource_by_content != resource_by_name:
            # Используем содержимое при несоответствии
            return resource_by_content
    
    return resource_by_name
```

**Проблемы:**
- ⚠️ Вызывается с `raw_json=None` при загрузке
- ⚠️ Анализ содержимого происходит только если не определили по имени
- ⚠️ Нет приоритета содержимого над именем файла

## 4. 🎯 Рекомендации по улучшению

### 4.1 Критические улучшения

1. **Перенести определение типа ресурса ПОСЛЕ парсинга**
   - Определять тип при загрузке только если указан пользователем
   - После парсинга переопределять тип на основе содержимого
   - Использовать имя файла только как fallback

2. **Улучшить анализ содержимого**
   - Добавить анализ единиц измерения (кВт·ч, м³, Гкал)
   - Добавить анализ структуры данных (временные ряды, кварталы)
   - Добавить анализ числовых паттернов

3. **Добавить валидацию соответствия типа и содержимого**
   - После парсинга проверять соответствие указанного типа и содержимого
   - Предупреждать пользователя о несоответствии
   - Предлагать автоматическое исправление

### 4.2 Улучшения средней приоритетности

1. **Унифицировать логику определения типа**
   - Создать единый модуль классификации
   - Использовать его во всех местах (загрузка, агрегация, специализированные парсеры)

2. **Добавить анализ структуры данных**
   - Определять временные ряды
   - Определять квартальные данные
   - Определять структуру таблиц

3. **Улучшить обработку ошибок**
   - Логировать случаи неопределения типа
   - Предоставлять пользователю информацию о проблеме
   - Предлагать варианты исправления

### 4.3 Долгосрочные улучшения

1. **Машинное обучение для классификации**
   - Обучить модель на примерах файлов
   - Использовать для повышения точности классификации

2. **Интерактивное определение типа**
   - Показывать пользователю предварительный анализ
   - Позволять корректировать тип вручную
   - Сохранять выбор для обучения системы
