### 1. 🔴 SECURITY CRITICAL: Hardcoded API Key в коде

**Файл:** `eaip_full_skeleton/services/ingest/utils/gemini_vision_ocr.py`  
**Строка:** 657

```python
# Настройка API ключа
genai.configure(api_key="AIzaSyAsULYwKTApWIppPOQHMCBJlZoOyBE6l10")
```

**Риски:**
- ✋ API ключ Google Gemini **хардкоден в коде**
- ✋ Ключ виден в Git истории (если был закоммичен)
- ✋ Потенциальная утечка при публикации кода
- ✋ Невозможность ротации ключа без изменения кода
- ✋ Возможное нецелевое использование ключа третьими лицами

**Действия:**
1. **НЕМЕДЛЕННО:** Отозвать скомпрометированный API ключ в Google Cloud Console
2. **НЕМЕДЛЕННО:** Сгенерировать новый ключ
3. Перенести ключ в переменную окружения:
   ```python
   # БЫЛО (ОПАСНО):
   genai.configure(api_key="AIzaSyAsULYwKTApWIppPOQHMCBJlZoOyBE6l10")
   
   # ДОЛЖНО БЫТЬ:
   import os
   api_key = os.getenv("GEMINI_API_KEY")
   if not api_key:
       raise ValueError("GEMINI_API_KEY не установлен в переменных окружения")
   genai.configure(api_key=api_key)
   ```
4. Добавить `GEMINI_API_KEY` в `.env` файл
5. Убедиться, что `.env` в `.gitignore`
6. Проверить Git историю на наличие ключа: `git log -S "AIzaSyAsULYwKTApWIppPOQHMCBJlZoOyBE6l10"`
7. При необходимости очистить историю: `git filter-branch` или BFG Repo-Cleaner

**Приоритет:** 🔴 CRITICAL - НЕМЕДЛЕННО  
**Время на исправление:** 30 минут  
**Блокирует:** Публичный релиз, безопасность API

### 3. 🟠 HIGH: 300+ пустых или слишком общих except блоков

**Проблема:** По всему проекту найдено 300+ случаев обработки ошибок типа:
```python
except:
    pass

except Exception:
    pass

except Exception as e:
    # Логируется, но программа продолжает работу
```

**Примеры критичных мест:**
- `tools/fill_energy_passport.py` - 20+ пустых except блоков при работе с Excel
- `tools/test_*.py` - тесты молча проглатывают ошибки
- `eaip_full_skeleton/services/ingest/file_parser.py` - парсинг может завершиться без данных

**Риски:**
- Тихие ошибки, которые невозможно отследить
- Некорректные данные в БД без предупреждения
- Сложность отладки в продакшене
- Невозможность понять причину проблемы

**Действия:**
1. Аудит всех `except` блоков в критичных модулях:
   - `fill_energy_passport.py`
   - `file_parser.py`
   - `main.py` и его дубликаты
   - `database.py`
2. Заменить на специфичные исключения:
   ```python
   # БЫЛО (ПЛОХО):
   try:
       value = float(cell.value)
   except:
       pass
   
   # ДОЛЖНО БЫТЬ (ХОРОШО):
   try:
       value = float(cell.value)
   except (ValueError, TypeError) as e:
       logger.warning(f"Не удалось преобразовать значение {cell.value}: {e}")
       value = 0.0
   except AttributeError:
       logger.error(f"Ячейка {cell.coordinate} не имеет значения")
       value = 0.0
   ```
3. Добавить логирование во все except блоки
4. Создать custom exceptions для бизнес-логики

**Приоритет:** 🟠 HIGH - В течение 1 недели  
**Время на исправление:** 3-5 дней  
**Блокирует:** Стабильность в продакшене
