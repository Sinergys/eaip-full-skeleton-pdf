# Схема работы: от загрузки файла до записи в базу данных

## Простое объяснение процесса

Представьте, что вы загружаете в систему файл Excel с данными об энергопотреблении. Система проходит несколько этапов, чтобы превратить этот файл в структурированные данные в базе данных.

## 📋 Детальное описание каждого этапа

### ЭТАП 1: Загрузка файла

**Что происходит:**
- Пользователь загружает файл через веб-интерфейс
- Система проверяет, что файл правильного формата (Excel, PDF, Word)
- Проверяется размер файла (не слишком большой)
- Проверяется, не загружался ли этот файл раньше (по хешу)

**Где сохраняется:**
- Файл → папка `inbox/` с именем `{batch_id}__{имя_файла}`
- Информация о загрузке → таблица `uploads` в базе данных

**Что такое batch_id?**
- Это уникальный номер загрузки, который присваивается каждому файлу
- Используется для связи всех данных одного файла

---

### ЭТАП 2: Парсинг (распознавание)

**Что происходит:**
- Система открывает файл и читает его содержимое
- Для Excel: читаются все листы, таблицы, числа, текст
- Для PDF: извлекается текст (иногда используется OCR для сканов)
- Для Word: читаются параграфы и таблицы

**Где сохраняется:**
- Распарсенные данные → таблица `parsed_data` в базе данных
- Формат: JSON (структурированные данные)
- Также создается текстовый вариант для редактирования

**Пример данных после парсинга:**
```json
{
  "sheets": {
    "Электроэнергия": [
      {"месяц": "Январь", "кВт·ч": 1000, "сумма": 5000},
      {"месяц": "Февраль", "кВт·ч": 1200, "сумма": 6000}
    ]
  }
}
```

---

### ЭТАП 3: Агрегация (группировка)

**Что происходит:**
- Система берет распарсенные данные и группирует их
- Группировка идет по:
  - **Типу ресурса**: электричество, газ, вода, тепло, топливо
  - **Периоду**: кварталы (2022-Q1, 2022-Q2, 2022-Q3, 2022-Q4)
- Для каждого ресурса и периода суммируются:
  - Объем потребления
  - Стоимость
  - Дополнительные параметры (активная/реактивная мощность для электричества)
- Добавляются категории использования:
  - На технологические нужды
  - На собственные нужды предприятия
  - На производственные нужды
  - На хозяйственно-бытовые нужды

**Где сохраняется:**
- Агрегированные данные → файл `aggregated/{batch_id}_aggregated.json`

**Пример структуры агрегированных данных:**
```json
{
  "resources": {
    "electricity": {
      "2022-Q1": {
        "year": 2022,
        "quarter": 1,
        "months": ["Январь", "Февраль", "Март"],
        "total_kwh": 3000,
        "total_cost": 15000,
        "by_usage": {
          "technological": 2000,
          "own_needs": 500,
          "production": 300,
          "household": 200
        }
      }
    },
    "gas": {
      "2022-Q1": {
        "year": 2022,
        "quarter": 1,
        "total_m3": 5000,
        "total_cost": 25000
      }
    }
  }
}
```

---

### ЭТАП 4: Импорт в базу данных

**Что происходит:**
- Система читает файл `aggregated/{batch_id}_aggregated.json`
- Для каждого ресурса и каждого периода:
  - Проверяется, есть ли уже запись в таблице `aggregated_data`
  - Если запись есть → обновляется
  - Если записи нет → создается новая

**Где сохраняется:**
- Таблица `aggregated_data` в базе данных

**Структура записи в таблице:**
- `id` - уникальный номер записи
- `enterprise_id` - номер предприятия
- `batch_id` - номер загрузки (связь с файлом)
- `resource_type` - тип ресурса (electricity, gas, water...)
- `period` - период (2022-Q1, 2022-Q2...)
- `data_json` - все данные в формате JSON
- `created_at` - когда создана запись
- `updated_at` - когда обновлена запись

**Важно:**
- Одна запись = один ресурс + один период
- Если у вас электричество за 4 квартала, будет 4 записи
- Если у вас 3 ресурса (электричество, газ, вода) за 4 квартала, будет 12 записей

## 🔄 Что происходит, если что-то пошло не так?

### Если файл уже загружался:
- Система находит дубликат по хешу файла
- Возвращает информацию о предыдущей загрузке
- Новый файл не сохраняется

### Если парсинг не удался:
- Запись в таблице `uploads` получает статус `error`
- В логах записывается ошибка
- Пользователь видит сообщение об ошибке

### Если агрегация не удалась:
- Файл `aggregated/{batch_id}_aggregated.json` не создается или создается пустым
- В логах записывается ошибка
- Импорт в БД не происходит

### Если импорт в БД не удался:
- Файл `aggregated/{batch_id}_aggregated.json` остается на диске
- Можно запустить импорт вручную позже
- В логах записывается ошибка

---

## 📁 Где что хранится?

### На диске:
- `inbox/` - загруженные файлы
- `aggregated/` - агрегированные данные (JSON файлы)
- `logs/` - логи работы системы

### В базе данных:

**Таблица `enterprises`:**
- Список предприятий

**Таблица `uploads`:**
- Информация о каждой загрузке файла
- Связь с предприятием
- Статус обработки

**Таблица `parsed_data`:**
- Распарсенные данные из файлов
- Связь с загрузкой через `upload_id`

**Таблица `aggregated_data`:**
- Финальные агрегированные данные
- Готова для использования в отчетах и паспортах

---

## ✅ Итоговая схема данных

```
Файл Excel
    │
    ▼
[Парсинг] → parsed_data (JSON в БД)
    │
    ▼
[Агрегация] → aggregated/{batch_id}_aggregated.json (файл)
    │
    ▼
[Импорт в БД] → aggregated_data (таблица в БД)
    │
    ▼
Готово для использования в отчетах!
```

---

## 🎯 Зачем нужен каждый этап?

1. **Парсинг** - превращает файл в структурированные данные
2. **Агрегация** - группирует данные по ресурсам и периодам, делает их удобными для анализа
3. **Импорт в БД** - сохраняет данные в базе для быстрого доступа и использования в отчетах

---

## 💡 Простая аналогия

Представьте, что вы получили коробку с разными документами:

1. **Загрузка** - вы кладете коробку на стол
2. **Парсинг** - вы достаете все документы и читаете их содержимое
3. **Агрегация** - вы сортируете документы по папкам (электричество, газ, вода) и по периодам (кварталы)
4. **Импорт в БД** - вы записываете информацию из папок в специальную книгу учета

В итоге у вас есть структурированная информация, которую легко найти и использовать!
