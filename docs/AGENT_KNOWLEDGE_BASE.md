## 🎯 О ПРОЕКТЕ

**EAIP** (Energy Audit Information Platform) - платформа для энергетического аудита предприятий.

**Основная цель:** Автоматизация обработки данных энергопотребления и генерация отчётов по стандарту ПКМ №690 (Узбекистан).

## 🔑 КЛЮЧЕВЫЕ МОДУЛИ

### 1. Сервис загрузки данных (ingest)

**Основной файл:** `eaip_full_skeleton/services/ingest/main.py`

**Функции:**
- Загрузка файлов (Excel, PDF, Word)
- Парсинг данных
- Агрегация энергопотребления
- Сохранение в БД

**Ключевые модули:**
- `database.py` - работа с SQLite БД
- `file_parser.py` - парсинг файлов
- `energy_aggregator.py` - агрегация данных
- `gemini_vision_ocr.py` - OCR через Gemini Vision API

### 2. OCR модуль

**Основной файл:** `eaip_full_skeleton/services/ingest/utils/gemini_vision_ocr.py`

**Функции:**
- Извлечение текста из изображений
- Распознавание таблиц
- Постобработка данных (числа, ID коды)
- Адаптивная обработка при низком confidence

**Конфигурация:** `config/ocr.yml`

### 3. Агрегатор данных

**Основной файл:** `eaip_full_skeleton/services/ingest/utils/energy_aggregator.py`

**Функции:**
- Агрегация поквартальных данных
- Распределение по категориям потребления
- Генерация JSON для заполнения паспорта

### 4. Парсеры

- `equipment_parser.py` - парсинг оборудования
- `building_envelope_parser.py` - парсинг ограждающих конструкций
- `nodes_parser.py` - парсинг узлов учёта

## 🔧 КОНФИГУРАЦИЯ

### OCR настройки (`config/ocr.yml`)

**Пороги confidence:**
- Текст: 0.30 (30%)
- Числа: 0.60 (60%)
- Даты: 0.80 (80%)
- Таблицы: 0.70 (70%)

**API настройки:**
- Таймаут: 600 секунд (10 минут)
- Retry: 3 попытки
- Backoff: 2 секунды (базовое время)

### API ключи

**Хранятся в:** `infra/.env` (НЕ в git!)

**DeepSeek:**
- Переменная: `DEEPSEEK_API_KEY`
- Модель: `deepseek-chat`
- Использование: ИИ обработка документов

**Gemini:**
- Переменная: `GOOGLE_API_KEY`
- Модель: `gemini-2.0-flash`
- Использование: OCR распознавание

## 🔄 ОБЯЗАТЕЛЬНОЕ ЧТЕНИЕ ФАЙЛОВ ПРИ СТАРТЕ

### ⚠️ КРИТИЧЕСКИ ВАЖНО: Все агенты ОБЯЗАНЫ читать необходимые файлы при старте работы!

**Перед началом работы каждый агент ДОЛЖЕН загрузить ОБЯЗАТЕЛЬНЫЕ файлы (2 файла, ~44.79 КБ):**

#### ✅ ОБЯЗАТЕЛЬНЫЕ ФАЙЛЫ:

1. **`docs/AGENT_CONTEXT.json`** (7.06 КБ)
   - Единый файл контекста
   - Содержит все критически важные настройки

2. **`docs/AGENT_TASKS_UNIFIED.json`** (37.72 КБ)
   - Единый файл задач
   - Источник правды для всех задач

**Использование утилиты:**
```python
from tools.context_loader import load_critical_context

# Загрузка обязательных файлов
context_data = load_critical_context()
# context_data["context"] - AGENT_CONTEXT.json
# context_data["tasks"] - AGENT_TASKS_UNIFIED.json
```

#### 💡 ОПЦИОНАЛЬНЫЕ ФАЙЛЫ (загружать по требованию):

- `docs/AGENT_TASK_STATUS.json` (0.40 КБ) - при выборе задачи
- `docs/AGENT_LOCKS.json` (0.17 КБ) - при блокировке задачи
- `docs/AGENT_SESSION_STATE.json` (2.61 КБ) - при восстановлении состояния
- `docs/AGENT_KNOWLEDGE_BASE.md` (7.70 КБ) - при необходимости справки
- `docs/PROJECT_CRITICAL_SETTINGS.md` (6.61 КБ) - как справочник

**Использование:**
```python
from tools.context_loader import load_optional_file

# Загрузка опционального файла
task_status = load_optional_file("task_status")
locks = load_optional_file("locks")
```

**Правило:** НЕ полагаться на контекст сеанса! ВСЕГДА читать актуальные данные из файлов!

**Утилита:** `tools/context_loader.py`

## 📋 ПРАВИЛА РАБОТЫ

### Основные правила:
1. **Работа по блокам** - максимум 10 минут на блок
2. **TLDV отчёт** - после каждого блока
3. **Ожидание указаний** - после каждого блока
4. **Использование файлов** - настройки из файлов, не из контекста сеанса
5. **Отдельные скрипты** - использовать отдельные Python скрипты вместо inline-команд `python -c` для операций с импортами

### ⚠️ Важно: Работа с Python командами

**Проблема:** Inline-команды `python -c "from tools..."` могут вызывать зависания и ошибки импорта.

**Правило:**
- ✅ **ИСПОЛЬЗОВАТЬ:** Отдельные скрипты в `tools/` для операций с импортами
- ❌ **ИЗБЕГАТЬ:** Inline-команды `python -c "from tools..."`
- ✅ **ПРИМЕР:** Создать `tools/update_task_status.py` вместо inline-команды

**Когда можно использовать inline-команды:**
- ✅ Простые операции без импортов: `python -c "print('test')"`
- ✅ Проверка переменных: `python -c "import os; print(os.getenv('VAR'))"`
- ❌ **НЕ использовать** для импортов из `tools/` или других модулей проекта

**Полные правила:** `docs/PROJECT_WORK_RULES.md`
