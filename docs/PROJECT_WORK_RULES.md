## 🎯 ОСНОВНОЕ ПРАВИЛО: РАБОТА ПО БЛОКАМ

### Обязательные требования:

1. **Разбиение на блоки**
   - Каждое задание **ОБЯЗАТЕЛЬНО** разбивается на блоки
   - Максимальное время выполнения одного блока: **10 минут**
   - Если задача больше 10 минут - разбить на подзадачи

2. **TLDV после каждого блока**
   - После завершения каждого блока **ОБЯЗАТЕЛЬНО** создается краткое резюме (TLDV - Too Long Didn't View)
   - TLDV содержит:
     - Что сделано
     - Что получено
     - Следующий шаг
   - Формат: 3-5 предложений

3. **Ожидание указания пользователя**
   - После каждого блока работа **ПРЕКРАЩАЕТСЯ**
   - ИИ **ОЖИДАЕТ** указания пользователя для продолжения
   - Не продолжать работу без явного разрешения

4. **Автоматическое выполнение**
   - ИИ **ВСЕГДА** должен выполнять эти правила **БЕЗ НАПОМИНАНИЯ** пользователем
   - Правила применяются ко **ВСЕМ** задачам проекта

```
## БЛОК N: [Название задачи]

⏸️ **ОЖИДАНИЕ УКАЗАНИЯ ПОЛЬЗОВАТЕЛЯ**
```

## 📏 ПОДДЕРЖАНИЕ ОПТИМАЛЬНОГО РАЗМЕРА ФАЙЛОВ

### ⚠️ ВАЖНО: Файлы должны поддерживаться в оптимальном размере!

**Проблема:** Большие файлы замедляют работу агентов и увеличивают время загрузки.

**Правила:**

1. **Максимальные размеры файлов:**
   - JSON файлы: **не более 1 МБ** (1,048,576 байт)
   - Markdown файлы: **не более 500 КБ** (524,288 байт)
   - Логи (JSONL): **не более 10 МБ** (10,485,760 байт)

2. **Автоматическая проверка:**
   - Перед записью в файл проверять его размер
   - Если файл превышает лимит - архивировать старые данные
   - Сохранять только актуальные данные

3. **Архивация:**
   - Старые данные перемещать в `docs/archive/`
   - История ограничивать последними 50-100 записями
   - Логи ротировать (сохранять только последние N записей)

4. **Оптимизация:**
   - Удалять устаревшие записи
   - Сжимать повторяющиеся данные
   - Использовать ссылки вместо дублирования

**Ответственность:** Все агенты обязаны проверять размер файлов перед записью!

## 🐍 РАБОТА С PYTHON КОМАНДАМИ И ИМПОРТАМИ

### ⚠️ ВАЖНО: Использование отдельных скриптов вместо inline-команд!

**Проблема:** Inline-команды `python -c "from tools..."` могут вызывать:
- Зависания при выполнении
- Ошибки импорта и циклические зависимости
- Проблемы с обработкой кавычек в PowerShell/CMD

**Правила:**

1. **Использование отдельных скриптов:**
   - ✅ **ИСПОЛЬЗОВАТЬ:** Отдельные Python скрипты для операций с импортами
   - ❌ **ИЗБЕГАТЬ:** Inline-команды `python -c "from tools..."`
   - ✅ **ПРИМЕР:** Создать `tools/update_task_status.py` вместо `python -c "from tools.unified_tasks_manager import update_task..."`

2. **Когда можно использовать inline-команды:**
   - ✅ Простые операции без импортов: `python -c "print('test')"`
   - ✅ Проверка переменных окружения: `python -c "import os; print(os.getenv('VAR'))"`
   - ❌ **НЕ использовать** для операций с импортами из `tools/` или других модулей проекта

3. **Создание скриптов:**
   - Скрипты должны быть в директории `tools/`
   - Название должно отражать назначение: `update_task_status.py`, `check_file_sizes.py`
   - Скрипты должны поддерживать аргументы командной строки для гибкости

**Ответственность:** Все агенты обязаны использовать отдельные скрипты для операций с импортами!
