# Анализ проблем и предложения по улучшению системы обработки данных

## Дата: 2025-11-26

## Выявленные проблемы

### 1. Загрузка файлов не показывает проблем при загрузке

**Проблема:**
- Все файлы показываются как успешно загруженные (✓ Загружено)
- Ошибки обнаруживаются только при проверке готовности данных (88%)
- Пользователь не видит проблем до момента генерации паспорта

**Причина:**
- Эндпоинт `/web/upload` только сохраняет файл и парсит его в `raw_json`
- Нет валидации структуры данных на этапе загрузки
- Нет проверки соответствия данных ожидаемым шаблонам
- Статус `success` устанавливается только при успешном парсинге, без проверки содержимого

**Текущий процесс:**
```
Загрузка → Парсинг → Сохранение в БД → Статус "success"
                    ↓
            (Нет проверки структуры)
```

### 2. Распознавание данных дает много ошибок

**Проблема:**
- `gas.volume_m3` не находится (хотя данные есть в файле)
- `gas.quarter_totals` не находится
- `nodes` (узлы учета) не распознаются
- `envelope.sections` и `envelope.items` не распознаются

**Причины:**

#### 2.1. Проблема с gas данными:
- Fallback-логика добавлена в `readiness_validator.py` (строки 1458-1488)
- Но она работает только при валидации, а не при парсинге
- Парсер `energy_aggregator.py` не всегда правильно извлекает данные из файла "Расчет газа для отопл и неотпл.xlsx"
- Структура файла отличается от ожидаемой (gaz.xlsx)

#### 2.2. Проблема с nodes:
- Парсер `nodes_parser.py` работает, но данные могут не сохраняться в правильном формате
- Валидатор ищет `nodes` в агрегированных данных, но они хранятся отдельно в JSON файлах

#### 2.3. Проблема с envelope:
- Парсер `building_envelope_parser.py` работает, но данные хранятся отдельно
- Валидатор не находит `envelope.sections` и `envelope.items` в агрегированных данных

**Текущая архитектура:**
```
Парсинг → Агрегация → Сохранение JSON → Валидация
         ↓              ↓                    ↓
    energy_aggregator  aggregated.json   readiness_validator
    nodes_parser       nodes.json        (ищет в aggregated)
    envelope_parser    envelope.json
```

**Проблема:** Валидатор ищет данные в агрегированных данных, но nodes и envelope хранятся отдельно.

### 3. Отсутствие анализа структуры файла при загрузке

**Проблема:**
- Нет анализа структуры файла при загрузке
- Если структура отличается от ожидаемой, файл все равно загружается
- Ошибки обнаруживаются только при валидации

**Текущее состояние:**
- Парсеры жестко привязаны к определенным структурам
- Нет адаптации к различным форматам
- Нет использования ИИ для анализа структуры (хотя есть модуль `ai_excel_semantic_parser`)

### 4. Отсутствие автоматической коррекции загрузки

**Проблема:**
- Данные парсятся, но если структура отличается, они не корректируются
- Нет автоматической адаптации к различным форматам
- Нет исправления ошибок парсинга на основе найденных данных

## Предложения по решению

### Решение 1: Валидация структуры данных при загрузке

**Цель:** Показывать проблемы сразу при загрузке файла

**Реализация:**

1. **Добавить валидацию структуры после парсинга:**
   ```python
   # В main.py после парсинга
   validation_result = validate_file_structure(
       parsing_result, 
       filename, 
       resource_type
   )
   
   if not validation_result["valid"]:
       # Устанавливаем статус "warning" или "partial"
       status = "warning"
       warnings = validation_result["warnings"]
   ```

2. **Создать модуль `file_structure_validator.py`:**
   - Проверка наличия обязательных полей
   - Проверка структуры данных
   - Проверка соответствия ожидаемому формату
   - Генерация предупреждений

3. **Обновить ответ загрузки:**
   ```python
   {
       "batch_id": "...",
       "status": "success" | "warning" | "error",
       "warnings": [...],
       "structure_validation": {
           "valid": bool,
           "issues": [...],
           "suggestions": [...]
       }
   }
   ```

**Преимущества:**
- Пользователь видит проблемы сразу
- Можно исправить файл до генерации паспорта
- Улучшенный UX

### Решение 2: Улучшение парсинга и агрегации данных

**Цель:** Правильно извлекать данные из файлов с различной структурой

**Реализация:**

#### 2.1. Улучшить парсинг gas данных:

1. **Расширить `energy_aggregator.py`:**
   - Добавить поддержку различных структур файлов газа
   - Использовать ИИ для определения структуры
   - Автоматически вычислять `quarter_totals` из месячных данных

2. **Унифицировать хранение данных:**
   - Все данные (gas, nodes, envelope) должны быть в агрегированных данных
   - Или валидатор должен искать данные в правильных местах

#### 2.2. Интегрировать nodes и envelope в агрегированные данные:

1. **Обновить `_get_aggregated_data_for_enterprise`:**
   ```python
   # Загружать nodes и envelope из JSON файлов
   nodes_file = AGGREGATED_DIR / f"{batch_id}_nodes.json"
   envelope_file = AGGREGATED_DIR / f"{batch_id}_envelope.json"
   
   if nodes_file.exists():
       all_aggregated["nodes"] = load_nodes_from_json(nodes_file)
   
   if envelope_file.exists():
       all_aggregated["envelope"] = load_envelope_from_json(envelope_file)
   ```

2. **Обновить валидатор:**
   - Искать nodes и envelope в правильных местах
   - Проверять как агрегированные данные, так и отдельные JSON файлы

#### 2.3. Улучшить fallback-логику:

1. **Перенести fallback-логику в парсер:**
   - Вычислять `quarter_totals` сразу при парсинге
   - Сохранять вычисленные значения в агрегированных данных

2. **Добавить fallback для всех ресурсов:**
   - Не только для gas, но и для electricity, water и т.д.

### Решение 3: Анализ структуры файла с использованием ИИ

**Цель:** Автоматически определять структуру файла и адаптироваться к ней

**Реализация:**

1. **Использовать существующий модуль `ai_excel_semantic_parser`:**
   ```python
   from ai.ai_excel_semantic_parser import analyze_excel_sheet, AnalyzeSheetInput
   
   # При загрузке файла
   ai_analysis = analyze_excel_sheet(
       AnalyzeSheetInput(
           sheet_name=sheet.title,
           header_rows=header_rows,
           sample_rows=sample_rows,
           language_hints=["ru", "uz"]
       )
   )
   
   # Использовать результаты для адаптации парсера
   if ai_analysis.confidence > 0.8:
       # Использовать структуру, определенную ИИ
       parse_with_ai_structure(workbook, ai_analysis)
   ```

2. **Создать адаптивный парсер:**
   - Анализировать структуру файла
   - Определять колонки с данными
   - Адаптироваться к различным форматам

3. **Сохранять метаданные структуры:**
   ```python
   {
       "structure_analysis": {
           "detected_format": "...",
           "confidence": 0.95,
           "column_mapping": {...},
           "ai_used": True
       }
   }
   ```

**Преимущества:**
- Поддержка различных форматов файлов
- Автоматическая адаптация
- Меньше ошибок парсинга

### Решение 4: Автоматическая коррекция данных

**Цель:** Автоматически исправлять ошибки парсинга и корректировать данные

**Реализация:**

1. **Создать модуль `data_corrector.py`:**
   ```python
   def correct_parsed_data(parsed_data, structure_analysis):
       """
       Корректирует распарсенные данные на основе анализа структуры
       """
       # Исправление ошибок
       # Заполнение пропущенных данных
       # Нормализация форматов
       # Вычисление производных данных
   ```

2. **Добавить этап коррекции после парсинга:**
   ```python
   # После парсинга
   corrected_data = correct_parsed_data(
       parsing_result,
       structure_analysis
   )
   
   # Сохранять исправленные данные
   ```

3. **Логировать изменения:**
   ```python

       "corrections": [

           }
       ]
   }
   ```

- Автоматическое исправление ошибок
- Улучшенное качество данных
- Меньше ручной работы
