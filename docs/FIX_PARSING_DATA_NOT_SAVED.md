# 🔧 Отчет об исправлении проблемы "Данные парсинга не найдены в БД"

**Дата:** 2025-11-30  
**Проблема:** После загрузки файла данные парсинга не сохраняются в БД  
**Симптом:** `"parsing": null, "error": "Данные парсинга не найдены в БД"`

---

## 🔍 Анализ проблемы

### Симптомы:
- Файл загружен успешно (статус: success)
- Но `parsing` равен `null`
- Ошибка: "Данные парсинга не найдены в БД"
- Данные не доступны через API

### Возможные причины:

1. **Данные не сохраняются в кэш:**
   - `parsing_results_cache[batch_id]` может быть пустым
   - Ошибка при парсинге может не сохранить данные в кэш

2. **Ошибка при сохранении в БД:**
   - `save_parsed_content` может выбрасывать исключение
   - Ошибка не логируется должным образом

3. **Файл загружен как дубликат:**
   - Если файл уже был загружен, обработка может не пройти полностью
   - Данные могут не сохраниться

4. **Слишком большой JSON:**
   - Если `raw_json` слишком большой, может быть ошибка сериализации
   - SQLite может не принять слишком большой TEXT

## ✅ Выполненные исправления

### 1. Добавлена проверка данных в кэше перед сохранением

**Файл:** `eaip_full_skeleton/services/ingest/main.py`

**Изменения:**
- Проверка наличия данных в `parsing_results_cache` перед сохранением
- Создание минимальной структуры, если данных нет в кэше
- Детальное логирование процесса

```python
# Проверяем, что данные есть в кэше перед сохранением
if batch_id not in parsing_results_cache:
    logger.error(f"⚠️ Данные парсинга отсутствуют в кэше для batch_id={batch_id}")
    # Создаем минимальную структуру из доступных данных
    parsing_results_cache[batch_id] = {
        "batch_id": batch_id,
        "filename": safe_filename,
        "file_path": dst,
        "file_type": file_type_label,
        "file_size": file_size,
        "parsing": parsing_result_data if parsing_result else None,
        "status": parsing_status,
        "error": "Данные парсинга не были сохранены в кэш",
    }
```

### 2. Добавлена обработка ошибок при сохранении

**Файл:** `eaip_full_skeleton/services/ingest/main.py`

**Изменения:**
- Обработка исключений при вызове `save_parsed_content`
- Детальное логирование ошибок
- Ошибка не прерывает обработку, но логируется

```python
try:
    database.save_parsed_content(
        batch_id,
        raw_json=parsing_results_cache[batch_id],
        editable_text=editable_text,
    )
    logger.info(f"✅ Данные парсинга успешно сохранены в БД для batch_id={batch_id}")
    tracker.complete_stage(ProcessingStage.SAVING, "Данные сохранены")
except Exception as save_exc:
    logger.error(
        f"❌ Ошибка сохранения данных парсинга в БД для batch_id={batch_id}: {save_exc}",
        exc_info=True
    )
    tracker.set_error(ProcessingStage.SAVING, f"Ошибка сохранения: {save_exc}")
    # Не прерываем обработку, но логируем ошибку
```
