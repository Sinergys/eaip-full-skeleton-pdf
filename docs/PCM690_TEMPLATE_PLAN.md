## 📚 Нормативная база и входные артефакты
- **ПКМ №690 (Узбекистан)** — требуется выгрузить актуальную редакцию и разметить обязательные таблицы/графики.
- Уже имеющиеся отчёты/паспорт из Demo (`infra/data/inbox/*.xlsx`, `infra/data/inbox/*.pdf`) — как эталон структуры и полей.
- Данные ingest: результат парсинга (`raw_json.parsing.data`), редактируемый текст, справочники предприятий.

**Действия:**
1. Получить утверждённый шаблон энергопаспорта и отчёта (если отсутствует — запросить у заказчика).
2. Составить перечень полей, обязательных диаграмм и формулировок из нормативного документа.
3. Зафиксировать расхождения между демо‑шаблонами и требованиями ПКМ №690.

## 📊 Excel-шаблон энергопаспорта

**Структура:**
- Лист `Summary`: метаданные предприятия, период, паспортные данные.
- Листы по видам энергоресурсов (газ, электроэнергия, тепло, вода).
- Лист `Analytics`: агрегированные показатели, KPI, сравнение периодов.

**Placeholder’ы:**
- `{{enterprise.name}}`, `{{period.start}}`, `{{period.end}}`, `{{kpi.total_consumption}}` и др.
- Таблицы с именованными диапазонами (`NamedRanges`) для автозаполнения.

**Диаграммы:**
- Гистограммы потребления по месяцам (столбчатые диаграммы) с данными из NamedRange.
- Стэковые диаграммы для сравнения норматив/факт.
- Спарклайны для 12-месячных трендов (опционально).

**Технические требования:**
- Формулы и форматы не должны ломаться при вставке строк — используем структурированные таблицы.
- Локализация: подписи и легенды на русском, допускаем последующее добавление узбекской локали.
- Подготовить лист `Instructions` с описанием полей.

## 📝 Word-шаблон отчёта

**Структура разделов:**
1. Титульный лист (логотип, реквизиты предприятия).
2. Содержание (автоматическое обновление полей).
3. Вводная часть (цель аудита, нормативная база).
4. Описание предприятия и процессов.
5. Анализ энергопотребления (таблицы + диаграммы).
6. Выявленные проблемы и рекомендации.
7. Приложения (таблицы, акты, фото).

**Placeholder’ы:** закладки (`{{...}}`) или контент-контролы (`Content Controls`) для текстовых блоков и таблиц.

**Гистограммы/диаграммы:**
- Предзаготовленные диаграммы (Embedded Excel) с NamedRange источниками.
- Вставки ссылок на изображения графиков, которые может генерировать отчётный сервис.

**Технические требования:**
- Единый стиль (шрифты, отступы, нумерация).
- Автоматическое обновление оглавления, списков рисунков/таблиц.
- Совместимость с `python-docx` или аналогичным генератором для дальнейшей автоматизации.

## 🔗 Интеграция с backend

1. **Обмен данными:** определить формат JSON → Excel/Word (ключи, массивы, вложенные секции).
2. **Service layer:** расширить ingest или reports сервис модулем шаблонизации (например, `openpyxl` + `python-docx`).
3. **Версионирование шаблонов:** хранить шаблоны в отдельной директории (`templates/pcm690/`) с указанием версии и даты.
4. **Проверка соответствия:** автоматический чеклист (pytest) сверяющий наличие обязательных листов/закладок.
