# Трассировка данных "Источник → Поле паспорта"

**Дата создания:** 2025-01-15  
**Версия:** 1.0

Данный документ описывает полную трассировку данных: откуда берется каждое поле энергопаспорта и как оно заполняется.

## Условные обозначения

- **Источник данных:**
  - `AGGREGATOR` - Данные из `energy_aggregator.py` (агрегированные квартальные данные)
  - `NODES_PARSER` - Данные из парсера узлов учета
  - `EQUIPMENT_PARSER` - Данные из парсера оборудования
  - `ENVELOPE_PARSER` - Данные из парсера ограждающих конструкций
  - `MANUAL_INPUT` - Ручной ввод
  - `NORMATIVE_DB` - Данные из БД нормативных документов
  - `CALCULATION` - Расчетное поле (формула)

- **Тип поля:**
  - `INPUT` - Входное поле
  - `CALCULATED` - Расчетное поле (формула)
  - `SUMMARY` - Итоговое поле (сумма)
  - `REFERENCE` - Ссылочное поле

## Проблемные поля и заглушки

### 1. Общее потребление (Структура пр 2, строка 9)

**Проблема:** Строка должна ссылаться на итоги листа "Баланс", но ссылка может быть потеряна.

**Текущее состояние:**
- Заполняется напрямую из `quarter_totals.active_kwh`
- Формула ссылки на "Баланс" не восстанавливается

**Рекомендация:**
- После заполнения "Баланс" восстановить формулу в "Структура пр 2": `=Баланс!F{row}`
- Или использовать валидацию для проверки равенства значений

### 2. Категории потребления (Баланс)

**Проблема:** Если `by_usage` отсутствует, используется fallback.

**Текущее решение:**
```python
if not by_usage:
    # Fallback: пропорции из yearly_total
    by_usage = {cat: (quarter_total * val / yearly_total) for cat, val in year_cats.items()}
```

**Рекомендация:**
- Явно сигнализировать об отсутствии данных
- Не заполнять заглушками без предупреждения

### 3. Удельный расход (Динамика ср, Расход на ед.п)

**Проблема:** Если производство = 0, удельный расход = 0, но это может скрывать отсутствие данных.

**Текущее решение:**
- Формула Excel: `=IF(G{row}>0,C{row}/G{row},0)`
- В коде: `if production_kg > 0: specific_consumption = active_kwh / production_kg else: 0`

**Рекомендация:**
- Проверять наличие данных производства перед расчетом
- Если производство отсутствует, оставлять поле пустым или сигнализировать

### 4. Срок окупаемости мероприятий

**Проблема:** Тарифы захардкожены в коде.

**Текущее решение:**
```python
tariff = 0.15 if "кВт·ч" in unit else 50.0
```

**Рекомендация:**
- Использовать тарифы из данных предприятия
- Или из БД нормативных документов (нормативные тарифы)

### 5. Квартальные маппинги

**Проблема:** Hardcoded маппинг только для 2022 года.

**Текущее решение:**
```python
def build_quarter_mapping() -> QuarterMapping:
    return {
        "2022-Q1": (9, 3, 4, 6, 14),
        "2022-Q2": (9, 19, 20, 22, 30),
        # ...
    }
```

**Рекомендация:**
- Универсальный маппинг для любых годов (динамический)
- См. `passport_field_mapping.build_quarter_mapping(year)`
