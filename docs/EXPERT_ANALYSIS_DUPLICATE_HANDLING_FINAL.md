## 🔍 АНАЛИЗ ПРЕДЛОЖЕННЫХ ВАРИАНТОВ

### Вариант 1: Минимальный
**Описание:**
- Добавить параметр `force_reprocess: bool = False` в API
- Оставить автоматическую логику как есть

### Вариант 2: Полный (рекомендуется)
**Описание:**
- `force_reprocess: bool = False`
- `reprocess_mode: str = "auto"` (auto | always | never)
- Batch endpoint для массовой загрузки
- Версионирование Router

### Вариант 3: Максимальный
**Описание:**
- Все из варианта 2
- UX диалог при дубликате
- История обработок
- Проверка hash файла

### ✅ ЕДИНОГЛАСНОЕ РЕШЕНИЕ

**Рекомендуется: Вариант 2 (Полный) с поэтапной реализацией**

### 📋 ПЛАН РЕАЛИЗАЦИИ

#### Фаза 1: MVP (Неделя 1-2)
1. ✅ Параметр `force_reprocess: bool = False`
2. ✅ Параметр `reprocess_mode: str = "auto"` (auto | always | never)
3. ✅ Версионирование Router (сохранять версию в routing_map)
4. ✅ Улучшить автоматическую логику (уже частично реализовано)

#### Фаза 2: Batch режим (Неделя 2-3)
5. ✅ Batch endpoint `/api/upload/batch`
6. ✅ Параметр `reprocess_existing: bool = True` для batch

#### Фаза 3: Улучшения (Неделя 3-4, опционально)
7. ⚠️ Проверка hash файла (для детекции обновлений)
8. ⚠️ Минимальный UI (чекбокс "Переобработать существующие")
9. ⚠️ История обработок (для аудита)

### 🎯 КРИТИЧЕСКИЕ ТРЕБОВАНИЯ

**Обязательно для MVP:**
1. ✅ `force_reprocess` - явный контроль пользователя
2. ✅ `reprocess_mode` - гибкость выбора
3. ✅ Версионирование Router - автоматическое обновление
4. ✅ Batch endpoint - для массовой загрузки

**Желательно (можно отложить):**
- История обработок
- Hash проверка
- UX диалог

### ⚠️ РИСКИ И МИТИГАЦИЯ

**Риск 1:** Сложность реализации batch режима
- **Митигация:** Начать с простого batch (последовательная обработка)

**Риск 2:** Производительность при массовой переобработке
- **Митигация:** Добавить очередь задач, лимиты

**Риск 3:** Пользователи не поймут режимы
- **Митигация:** Хорошая документация, значения по умолчанию
