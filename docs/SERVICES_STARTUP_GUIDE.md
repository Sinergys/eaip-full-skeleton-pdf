# 🚀 Руководство по запуску сервисов EAIP

## 📋 Два способа запуска сервисов

В проекте EAIP есть **два способа** запуска сервисов:

### 1. 🐳 **Через Docker (Production-подобный запуск)**
Все сервисы запускаются в контейнерах через `docker-compose`

### 2. 🐍 **Напрямую через Python (Разработка)**
Отдельные сервисы можно запускать напрямую для разработки и отладки

---

## 🐳 Способ 1: Запуск через Docker

### Когда использовать:
- ✅ Тестирование полной системы
- ✅ Проверка взаимодействия между сервисами
- ✅ Имитация production-среды
- ✅ Запуск всех сервисов одновременно

### Что запускается:

**EAIP Сервисы (7 штук):**
- `gateway-auth` - порт 8000
- `ingest` - порт 8001
- `validate` - порт 8002
- `analytics` - порт 8003
- `recommend` - порт 8004
- `reports` - порт 8005
- `management` - порт 8006

**Инфраструктура:**
- `postgres` - PostgreSQL база данных (порт 5432)
- `redis` - Redis кэш (порт 6379)
- `minio` - MinIO хранилище (порты 9000, 9001)

### Как запустить:

```bash
# Перейти в директорию infra
cd eaip_full_skeleton/infra

# Запустить все сервисы
docker compose up -d

# Или для локального mini-production (с мониторингом)
bash launch-local-mini-prod.sh
```

### Проверка статуса:

```bash
# Проверить запущенные контейнеры
docker ps

# Проверить логи конкретного сервиса
docker compose logs ingest

# Проверить health endpoints
curl http://localhost:8001/health  # ingest
curl http://localhost:8002/health  # validate
```

### Остановка:

```bash
# Остановить все сервисы
docker compose down

# Остановить и удалить volumes (БД будет очищена)
docker compose down -v
```

## 🐍 Способ 2: Запуск напрямую через Python

### Когда использовать:
- ✅ Разработка и отладка конкретного сервиса
- ✅ Быстрый запуск одного сервиса
- ✅ Изменение кода с автоперезагрузкой
- ✅ Отладка без Docker

### Текущее состояние:

**✅ Запущен:**
- `ingest` сервис на порту 8001 (процесс 7032)

**❌ Не запущены:**
- `gateway-auth` (порт 8000)
- `validate` (порт 8002)
- `analytics` (порт 8003)
- `recommend` (порт 8004)
- `reports` (порт 8005)
- `management` (порт 8006)

### Как запустить отдельный сервис:

#### Ingest сервис:
```bash
cd eaip_full_skeleton/services/ingest
python -m uvicorn main:app --reload --port 8001
```

#### Validate сервис:
```bash
cd eaip_full_skeleton/services/validate
python -m uvicorn main:app --reload --port 8002
```

#### Reports сервис:
```bash
cd eaip_full_skeleton/services/reports
python -m uvicorn main:app --reload --port 8005
```

### Преимущества прямого запуска:
- ✅ Быстрый старт
- ✅ Автоперезагрузка при изменении кода (`--reload`)
- ✅ Прямой доступ к логам в консоли
- ✅ Легче отлаживать

### Недостатки:
- ❌ Нужно запускать каждый сервис отдельно
- ❌ Нет автоматической настройки зависимостей (PostgreSQL, Redis)
- ❌ Нужно вручную настраивать переменные окружения

---

## 🔍 Как определить, какой способ используется?

### Проверка через Docker:
```bash
docker ps
```

**Если видите контейнеры** (ingest, validate, postgres и т.д.) → **Запущено через Docker**

**Если контейнеров нет** → **Запущено напрямую или не запущено**

### Проверка через порты:
```bash
# Windows PowerShell
netstat -ano | findstr ":8001"

# Linux/Mac
lsof -i :8001
```

**Если видите процесс** → **Сервис запущен (либо через Docker, либо напрямую)**

## 📊 Сравнение способов

| Критерий | Docker | Прямой запуск |
|---------|--------|---------------|
| **Скорость запуска** | Медленнее (сборка образов) | Быстрее |
| **Все сервисы сразу** | ✅ Да | ❌ Нужно запускать отдельно |
| **Автоперезагрузка** | ⚠️ Требует настройки | ✅ Да (`--reload`) |
| **Изоляция** | ✅ Полная | ❌ Общая среда |
| **Зависимости** | ✅ Автоматически | ❌ Нужно настраивать |
| **Для разработки** | ⚠️ Медленнее | ✅ Удобнее |
| **Для тестирования** | ✅ Лучше | ⚠️ Сложнее |

---

## 🎯 Рекомендации

### Для разработки:
1. **Используйте прямой запуск** для сервиса, над которым работаете
2. **Используйте Docker** для проверки взаимодействия с другими сервисами

### Для тестирования:
1. **Используйте Docker** для полного тестирования системы
2. Запускайте все сервисы через `docker compose up -d`

### Для production:
1. **Только Docker** - все сервисы должны быть в контейнерах
