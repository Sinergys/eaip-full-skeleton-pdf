# Отчет: Обработка нескольких листов в файлах "Реализация"

## Дата: 2025-11-30

## Проблема

Пользователь указал, что в файлах "Реализация" есть **2 листа**:
1. **Детальное по потребителям** - детальная информация по каждому потребителю
2. **Общее за год** - общая сводная информация за год

Текущая логика могла не обрабатывать оба листа, особенно если один из них не содержал стандартных ключевых слов в первых строках.

## Решение

Улучшена логика обработки файлов "Реализация" для корректной обработки обоих типов листов:
- Детальные данные по потребителям
- Общие данные за год

## Внесенные изменения

### 1. Улучшена функция `_extract_from_excel` (`balance_sheet_node_extractor.py`)

- Добавлена специальная обработка для файлов "Реализация"
- Для файлов "Реализация" используется функция `_is_realization_sheet` вместо стандартной `_is_node_sheet`
- Улучшено логирование: показывается количество листов и какие листы обрабатываются

### 2. Добавлена функция `_is_realization_sheet` (`balance_sheet_node_extractor.py`)

Новая функция специально для файлов "Реализация":
- Проверяет **20 строк** вместо 5 (для более тщательного анализа)
- Ищет ключевые слова:
  - Для детальных данных: "потребитель", "потребители", "детальн", "детально"
  - Для общих данных: "общее", "общий", "год", "годов", "итого", "итог"
  - Общие ключевые слова: "узел", "тп", "подстанция", "счетчик", "активная", "реактивная", "энергия"
- Проверяет наличие числовых данных как признак таблицы с данными
- Более гибкая логика определения: лист считается валидным, если есть:
  - Ключевые слова узлов И энергии (детальные данные)
  - ИЛИ числовые данные И (ключевые слова узлов ИЛИ энергии) (общие данные)

### 3. Улучшена функция `_parse_node_sheet` (`balance_sheet_node_extractor.py`)

- Добавлено определение типа листа:
  - `detail_by_consumers` - детальные данные по потребителям
  - `summary_by_year` - общие данные за год
  - `unknown` - если тип не определен
- Информация о типе листа сохраняется в `data_json.sheet_type`
- Добавлена фильтрация строк с итогами (для детальных листов)
- Улучшено логирование извлеченных данных

## Примеры работы

### Файл "Реализация 2022.xlsx" с 2 листами:

1. **Лист 1: "Детальное по потребителям"**
   - Система определяет как `detail_by_consumers`
   - Извлекает данные по каждому потребителю
   - Сохраняет в БД с `data_json.sheet_type = "detail_by_consumers"`

2. **Лист 2: "Общее за год"**
   - Система определяет как `summary_by_year`
   - Извлекает общие данные за год
   - Сохраняет в БД с `data_json.sheet_type = "summary_by_year"`

## Преимущества

1. **Обработка всех листов**: Теперь обрабатываются оба листа в файлах "Реализация"
2. **Различение типов листов**: Система различает детальные и общие данные
3. **Гибкость**: Более тщательная проверка листов (20 строк вместо 5)
4. **Прозрачность**: Улучшенное логирование показывает, какие листы обрабатываются
5. **Метаданные**: Информация о типе листа сохраняется в `data_json` для дальнейшего анализа

## Тестирование

Рекомендуется протестировать на файлах "Реализация" с 2 листами:
- Убедиться, что оба листа обрабатываются
- Проверить, что данные из обоих листов сохраняются в БД
- Проверить, что `data_json.sheet_type` правильно определяется
