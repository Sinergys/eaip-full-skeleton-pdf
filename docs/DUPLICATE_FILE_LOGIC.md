# 🔄 Логика обработки дубликатов файлов

## Проблема (исправлена)

**Старая логика:**
- При повторной загрузке файла система находила дубликат
- Если были данные парсинга - возвращала старую запись
- **Не переобрабатывала файл с новым Intelligent Router**

**Результат:**
- Файлы, загруженные до улучшений Router, оставались с устаревшими routing_map
- Невозможно было обновить анализ без удаления файла вручную

## Новая логика (исправлена)

### Алгоритм проверки дубликата:

1. **Найден дубликат** (по filename, file_size, file_hash)

2. **Проверка данных парсинга:**
   - Если данных парсинга нет → **переобработать**
   - Если данные есть → проверяем дальше

3. **Проверка routing_map:**
   - Если routing_map отсутствует → **переобработать**
   - Если routing_map есть, но confidence < 0.7 → **переобработать**
   - Если routing_map есть и confidence >= 0.7 → **вернуть существующую запись**

### Когда файл переобрабатывается:

✅ **Переобрабатывается, если:**
- Нет данных парсинга
- Нет routing_map в parsing_summary
- routing_map есть, но confidence < 0.7 (устаревший анализ)

✅ **Возвращается существующая запись, если:**
- Есть данные парсинга
- Есть routing_map с confidence >= 0.7

## Преимущества новой логики

1. **Автоматическое обновление** - старые файлы автоматически переобрабатываются при повторной загрузке
2. **Экономия ресурсов** - не переобрабатывает файлы с актуальным анализом
3. **Гибкость** - можно принудительно обновить анализ, просто перезагрузив файл

## Примеры работы

### Пример 1: Файл без routing_map
```
Загружен файл "т-3а.jpg" (старая версия)
→ routing_map отсутствует
→ При повторной загрузке → ПЕРЕОБРАБОТКА
→ Новый routing_map с confidence 100%
```

### Пример 2: Файл с низким confidence
```
Загружен файл "т-3а.jpg" (старая версия)
→ routing_map: {confidence: 0.48}
→ При повторной загрузке → ПЕРЕОБРАБОТКА
→ Новый routing_map с confidence 100%
```

### Пример 3: Файл с актуальным routing_map
```
Загружен файл "т-3а.jpg" (новая версия)
→ routing_map: {confidence: 0.95}
→ При повторной загрузке → ВОЗВРАТ СУЩЕСТВУЮЩЕЙ ЗАПИСИ
```

## Технические детали

### Код проверки:

```python
# Проверяем наличие routing_map
has_routing_map = False
routing_map_confidence = 0.0
if existing_record:
    parsing_summary = existing_record.get("parsing_summary")
    if parsing_summary:
        if isinstance(parsing_summary, str):
            parsing_summary = json.loads(parsing_summary)
        if isinstance(parsing_summary, dict) and "routing_map" in parsing_summary:
            routing_map = parsing_summary.get("routing_map", {})
            routing_map_confidence = routing_map.get("confidence", 0.0)
            has_routing_map = routing_map_confidence >= 0.7

# Решаем, нужно ли переобработать
should_reprocess = not has_parsing_data or not has_routing_map
```

## Рекомендации

1. **При обновлении Router** - просто перезагрузите файлы, они автоматически переобработаются
2. **Для принудительного обновления** - удалите старую запись или перезагрузите файл
3. **Для проверки** - используйте `tools/check_navoi_project.py` для просмотра routing_map
