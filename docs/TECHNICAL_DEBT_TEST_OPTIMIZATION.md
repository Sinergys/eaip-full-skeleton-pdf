## Проблема

E2E тесты выполняются слишком долго (7+ минут) из-за повторной загрузки одних и тех же файлов при каждом запуске.

- ✅ **Выполнено:** Изменен `SYSTEM_MODE` с `debug` на `production` в тестах
- ✅ **Выполнено:** Добавлена проверка существующих загрузок в фикстуру `uploaded_batches`
- ⏳ **В работе:** Изменение scope фикстур для кэширования данных

## План оптимизации

### Фаза 1: Кэширование фикстур (высокий приоритет)

**Задача:** Изменить scope фикстур с `function` на `session` для переиспользования данных между тестами.

**Файлы:**
- `eaip_full_skeleton/services/ingest/tests/conftest.py`
- `eaip_full_skeleton/services/ingest/tests/test_passport_e2e_audit_sinergys.py`

**Изменения:**
```python
# Было:
@pytest.fixture(scope="function")
def uploaded_batches(client: TestClient) -> List[str]:
    ...

# Должно быть:
@pytest.fixture(scope="session")
def uploaded_batches(client: TestClient) -> List[str]:
    ...
```

**Ожидаемый результат:** Сокращение времени тестов с 7+ минут до 1-2 минут.

### Фаза 2: Интеллектуальная проверка дубликатов

**Задача:** Улучшить логику проверки существующих загрузок.

**Требования:**
- Проверять не только наличие файла, но и его hash
- Сравнивать метаданные (размер, дата изменения)
- Предоставлять опцию принудительной перезагрузки

**API улучшения:**
```python
POST /api/upload-with-options
{
    "file": "...",
    "enterprise_id": 41,
    "options": {
        "skip_if_exists": true,
        "reload_if_changed": true,

    }

```

### Фаза 3: Слоистая архитектура тестов

**Задача:** Разделить тесты на слои для лучшей изоляции и производительности.

**Структура:**
```
Unit Tests      → Mock DB/API (быстрые, изолированные)
Integration     → Real DB, но предзаполненная (средняя скорость)
E2E            → Полный цикл, но с оптимизациями (медленные, но реалистичные)
```
