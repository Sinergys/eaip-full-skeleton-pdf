## 2. Улучшение структуры хранения файлов в INBOX_DIR

**Дата обнаружения:** 2025-12-05

**Суть проблемы:**
Текущая система добавляет `batch_id__` в начало имени файла для обеспечения уникальности:
```
INBOX_DIR/
  ├── 633b4bbf-7555-4dcf-bd15-9f0a368f77d1__test_file.xlsx
  ├── a12e3f4g-8899-4abc-def0-1234567890ab__report.xlsx
  └── ...
```

**Проблемы:**
- Имена файлов становятся длинными и нечитаемыми
- Сложно искать файлы вручную в INBOX_DIR
- Не информативно для пользователя
- Потенциальные проблемы с лимитом длины пути в Windows (260 символов)

**Предлагаемое решение:**
Использовать иерархическую структуру папок по предприятиям и batch_id:
```
INBOX_DIR/
  ├── {enterprise_id}/
  │   ├── {batch_id_1}/
  │   │   └── test_file.xlsx      # Чистое имя файла!
  │   └── {batch_id_2}/
  │       └── report.xlsx
  └── {enterprise_id_2}/
      └── ...
```

**Преимущества:**
- ✅ Чистые имена файлов (без UUID префиксов)
- ✅ Организованная структура по предприятиям
- ✅ Легко искать файлы конкретного предприятия
- ✅ Уникальность гарантирована (разные папки для каждой загрузки)
- ✅ Масштабируемость (легко добавить дополнительные уровни)

**Затронутые компоненты:**
- `main.py` — логика сохранения файлов (строка ~200: `dst = os.path.join(INBOX_DIR, f"{batch_id}__{safe_filename}")`)
- `database.py` — сохранение путей к файлам
- Все функции парсинга, которые читают файлы из INBOX_DIR
- Тесты (`test_api_e2e.py`) — проверка путей к файлам

**Приоритет:** Средний (не критично для функциональности, но улучшит UX)

**Следующие шаги:**
1. Создать функцию `get_file_storage_path(enterprise_id, batch_id, filename)` для генерации пути
2. Обновить логику сохранения файлов в `POST /web/upload`
3. Добавить миграцию для существующих файлов (опционально)
4. Обновить все места, где используются пути к файлам
5. Обновить тесты для новой структуры путей

## 3. Замена PyPDF2 fallback на PyMuPDF в file_parser.py

**Дата обнаружения:** 2025-12-05

**Суть проблемы:**
В `file_parser.py` используется устаревшая библиотека PyPDF2 как fallback механизм, если pdfplumber не справляется с парсингом PDF.

**Текущая архитектура:**
```python
# file_parser.py, функция parse_pdf_file()
# Шаг 1: Попытка через pdfplumber (основной метод)
if HAS_PDFPLUMBER:
    # Извлечение таблиц и текста через pdfplumber
    ...

# Шаг 2: Fallback на PyPDF2 (DEPRECATED!)
if HAS_PYPDF2:  # <- Устаревшая библиотека
    with open(file_path, "rb") as file:
        pdf_reader = PyPDF2.PdfReader(file)
        # Извлечение текста через PyPDF2
```

**Проблемы:**
- PyPDF2 deprecated с 2023 года, заменен на `pypdf`
- Предупреждение в тестах: `PyPDF2 is deprecated. Please move to the pypdf library`
- Ограниченная функциональность (не извлекает таблицы, медленный)
- Нет активной поддержки и обновлений

**Выполненные действия (2025-12-05):**
1. ✅ Обновлен `requirements.txt`: удален PyPDF2, добавлен PyMuPDF==1.24.0
2. ✅ Заменен импорт в `file_parser.py`: `import PyPDF2` → `import fitz  # PyMuPDF`
3. ✅ Изменена переменная: `HAS_PYPDF2` → `HAS_PYMUPDF`
4. ⏸️ **Старый код PyPDF2 оставлен без изменений** (безопасный подход)

**Что нужно сделать:**
Переписать fallback блок с использованием PyMuPDF (fitz):

```python
# БЫЛО (PyPDF2):
if HAS_PYPDF2:
    with open(file_path, "rb") as file:
        pdf_reader = PyPDF2.PdfReader(file)
        for page in pdf_reader.pages:
            page_text = page.extract_text() or ""
            # ...

# ДОЛЖНО БЫТЬ (PyMuPDF):
if HAS_PYMUPDF:
    doc = fitz.open(file_path)
    for page_num in range(len(doc)):
        page = doc[page_num]
        page_text = page.get_text() or ""
        # ...
    doc.close()
```

**Преимущества PyMuPDF:**
- ✅ В 5-10 раз быстрее PyPDF2
- ✅ Лучшее извлечение текста
- ✅ Поддержка изображений и метаданных
- ✅ Встроенная поддержка OCR
- ✅ Активная разработка и поддержка
- ✅ Совместим с pdf2image для конвертации в изображения

**Затронутые компоненты:**
- `file_parser.py` — функция `parse_pdf_file()` (строки ~750-850)
- Переменная `HAS_PYMUPDF` вместо `HAS_PYPDF2`
- Логика извлечения текста и метаданных

**Приоритет:** Низкий (не критично, т.к. основной парсинг через pdfplumber работает)

**Риски:**
- Изменение API извлечения текста может повлиять на качество парсинга
- Требуется тестирование на реальных PDF файлах
- Возможны различия в обработке специальных символов и кодировок

**План реализации:**
1. Создать тестовые PDF файлы (текстовые и сканированные)
2. Переписать блок fallback с PyPDF2 на PyMuPDF
3. Добавить обработку ошибок и логирование
4. Протестировать на всех типах PDF:
   - Текстовые PDF
   - Сканированные PDF (для OCR)
   - PDF с таблицами
   - PDF с кириллицей
5. Запустить полный набор тестов
6. Обновить документацию

**Тестирование:**
```python

1. parse_pdf_file("text_based.pdf")     # Текстовый PDF
2. parse_pdf_file("scanned.pdf")        # Сканированный (OCR)
```

**Примечание:**
Основной парсинг PDF идет через `pdfplumber`, который работает отлично. PyMuPDF fallback используется редко (только если pdfplumber не справился). Поэтому замена не критична для текущей функциональности, но улучшит производительность и уберет deprecated warning.


## 4. Исправление ошибки merged cells в fill_energy_passport.py

**Дата обнаружения:** 2025-12-06

**Суть проблемы:**
Ошибка `AttributeError: 'MergedCell' object attribute 'value' is read-only` в функции `_write_nodes_table` файла `fill_energy_passport.py` на строке 2175.

**Контекст:**
При записи данных в шаблон Excel "Метин" возникала ошибка при попытке записи в объединенные ячейки (merged cells). Функция `_write_nodes_table` использовала прямое присваивание:
```python
ws.cell(row=current_row, column=col_idx).value = value
```

**Выполненные действия (2025-12-06):**
1. ✅ Проанализирован существующий код проверки merged cells
2. ✅ Обнаружена функция `safe_cell_write` (строка 1693), которая уже содержит логику проверки
3. ✅ Изменены строки 2175 и 2180 в функции `_write_nodes_table`:
   - Было: `ws.cell(row=current_row, column=col_idx).value = value`
   - Стало: `safe_cell_write(ws.cell(row=current_row, column=col_idx), value)`

**Технический долг:**
1. **Пропуск данных:** Функция `safe_cell_write` возвращает `False` для merged cells, что означает пропуск записи данных. Если данные должны быть записаны, требуется дополнительная логика поиска свободных ячеек.
2. **Ограниченное решение:** Исправление решает проблему ошибки, но не гарантирует запись всех данных.
3. **Необходимость тестирования:** Требуется запуск теста `test_passport_generation_with_metin_template` для проверки корректности работы.

**Предлагаемые улучшения:**
1. **Функция поиска свободных ячеек:** Реализовать логику поиска альтернативных ячеек для записи данных.
2. **Расширенная проверка:** Добавить анализ структуры листа перед записью для определения безопасных зон.
3. **Рефакторинг файла:** Файл `fill_energy_passport.py` (2,246 строк) требует разделения на модули:
   - `excel_operations.py` (14 Excel-функций)
   - `utils.py` (вспомогательные функции)
   - `data_loaders.py` (функции загрузки данных)

**Приоритет:** Средний (ошибка исправлена, но требуется доработка для полного решения)

**Следующие шаги:**
1. Запустить тест `test_passport_generation_with_metin_template`
