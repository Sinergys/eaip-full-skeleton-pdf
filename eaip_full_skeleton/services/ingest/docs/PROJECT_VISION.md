## 0. ПРАВИЛА РАБОТЫ НАД ПРОЕКТОМ

### 0.1 Правила взаимодействия с ИИ-ассистентом
1. **Строго следовать инструкциям.** Не добавлять действий, шагов, решений или интерпретаций, не предусмотренных явной пользовательской командой.
2. **Действовать только после подтверждения.** Любое предложенное действие требует явного согласия ("да", "исполняй", "сделай") перед исполнением.
3. **Уточнять при неоднозначности.** Если запрос непонятен, неполон или допускает разные толкования — задавать уточняющие вопросы.
4. **Быть точным и обозначать границы знаний.** Не выдумывать факты. Если информация отсутствует — сообщить об этом.
5. **Отвечать по существу.** Ясный, прямой язык. Избегать лишних рассуждений и непрошенных советов.
6. **Разделять факты и предложения.** Чётко разграничивать проверенную информацию и гипотезы/варианты.
7. **Структурировать варианты.** Если нужны варианты — оформлять списком.

### 0.2 Правила оформления вопросов
- Подвопросы обозначать русскими буквами: а, б, в, г...
- Пользователь отвечает указанием буквы, без повторения текста

### 0.3 Мета-правило о документации
- В процессе работы сразу вносить результаты, решения и контекст в документацию
- Строго соблюдать требования к формату проекта

## 1. ЦЕЛЬ ПРОЕКТА

### 1.1 Основная задача
Автоматизация создания **энергетического паспорта (Excel)** и **Word-отчёта** согласно ПКМ №690 для предприятий Узбекистана.

### 1.2 Что делает система
| Функция | Описание | Статус |
|---------|----------|--------|
| Приём входных данных | Загрузка файлов с данными предприятия (Excel, PDF, Word) | ✅ Реализовано |
| Парсинг и извлечение | Автоматическое распознавание структуры и извлечение данных | ✅ Реализовано |
| Агрегация данных | Объединение данных из разных файлов, расчёт итогов по периодам | ✅ Реализовано |
| Расчёт показателей | Автоматический расчёт энергоэффективности, категории предприятия | ⚠️ Частично |
| Генерация паспорта | Заполнение Excel-шаблона энергопаспорта | ✅ Реализовано |
| Генерация Word-отчёта | Создание текстового отчёта по ПКМ 690 | ✅ Реализовано |
| Хранение нормативов | База нормативных документов и формул для расчётов | ✅ Реализовано |
| Хранение результатов | Сохранение паспортов и отчётов в системе | ✅ Реализовано |

### 1.3 Чего система НЕ делает (пока)
- Печать документов
- Отправка по email / в госорганы
- Регистрация и авторизация пользователей
- Проверка паспортов госорганами

## 2. ПОЛЬЗОВАТЕЛИ

### 2.1 Основной пользователь: Энергоаудитор
**Роль:** Специалист, проводящий энергоаудит предприятий

**Задачи:**
1. Собирает данные с предприятия (счета, акты, отчёты)
2. Загружает файлы в систему
3. Проверяет корректность распознавания
4. Генерирует паспорт и отчёт
5. Скачивает готовые документы
6. Печатает и подписывает бумажную версию

**Боли, которые решает система:**
- Ручное заполнение множества ячеек в Excel
- Ручной перенос данных из счетов в паспорт
- Ошибки при расчётах
- Несоответствие форматов и единиц измерения

### 2.2 Перспективный пользователь: Сотрудник предприятия
**Статус:** НЕ реализуется сейчас, архитектура может учитывать

**Возможные задачи:**
- Регистрация предприятия (ИНН, название, адрес)
- Загрузка своих данных о потреблении
- Просмотр статуса аудита

## 3. ВХОДНЫЕ ДАННЫЕ

### 3.1 Типы файлов
| Формат | Содержимое | Примеры |
|--------|------------|---------|
| Excel (.xlsx, .xlsm) | Данные потребления по периодам, оборудование, узлы учёта | pererashod.xlsx, equipment.xlsx |
| PDF | Акты балансов, счета, нормативные документы | balance_sheet.pdf |
| Word (.docx) | Готовые отчёты (если есть), справки | report.docx |

### 3.2 Категории данных
1. **Энергопотребление** — электричество, газ, вода, тепло, топливо по периодам
2. **Оборудование** — список оборудования с мощностью
3. **Узлы учёта** — счётчики, коэффициенты, даты поверки
4. **Здания/конструкции** — площади, теплопотери
5. **Реквизиты предприятия** — ИНН, название, адрес, отрасль
6. **Нормативы** — законы, формулы, коэффициенты из ПКМ 690

### 3.3 Привязка к предприятию
- При загрузке файла **обязательно** выбирается предприятие из меню
- Несколько файлов объединяются в данные одного предприятия
- Данные о других предприятиях в файлах = контрагенты (поставщики/потребители услуг)

### 5.2 Проверка полноты данных
| Аспект | Текущее состояние | Целевое состояние |
|--------|-------------------|-------------------|
| Чек-лист | Есть, но неточный | Точный чек-лист с детализацией |
| Момент проверки | При загрузке | Отдельная операция "Проверить данные" |
| Блокировка генерации | Работает (не даёт генерировать) | Оставить |

> **Задача:** Доработать точность чек-листа. Разбить на отдельный процесс "Выполнить проверку данных".
