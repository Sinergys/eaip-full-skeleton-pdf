## ТЕХНИЧЕСКИЕ ДЕТАЛИ

### Алгоритм fix_json_strings()

1. **Посимвольный парсинг:** Проходим по JSON символ за символом
2. **Отслеживание состояния:** Отслеживаем, находимся ли мы внутри строки (`in_string`)
3. **Обработка экранирования:** Учитываем уже экранированные символы (`escape_next`)
4. **Определение закрывающих кавычек:** Анализируем контекст после кавычки:
   - Если после кавычки (после пробелов) идет `:`, `,`, `]`, `}` или конец строки → закрывающая кавычка
   - Иначе → вложенная кавычка, экранируем как `\"`
5. **Обработка управляющих символов:**
   - `\n` → `\\n`
   - `\r` → `\\r`
   - `\t` → `\\t`
   - Другие управляющие символы (ord < 32) → удаляются

## ПРОБЛЕМЫ И РЕШЕНИЯ

### Проблема 1: Regex не обрабатывал вложенные кавычки
- **Описание:** Исходная реализация с regex `r'"([^"]*(?:\\.[^"]*)*)"'` не могла корректно обработать вложенные кавычки, так как останавливалась на первой встреченной кавычке
- **Решение:** Заменён на посимвольный парсинг с отслеживанием состояния строки
- **Статус:** ✅ Решено

### Проблема 2: Определение закрывающих кавычек
- **Описание:** Нужно было различать закрывающие кавычки строк и вложенные кавычки внутри строк
- **Решение:** Добавлен анализ контекста после кавычки (следующие символы после пробелов)
- **Статус:** ✅ Решено

### Проблема 3: Предупреждения о невалидных escape-последовательностях
- **Описание:** Python выдавал предупреждения о `':,\]}'` в строке
- **Решение:** Исправлено на `':,\\]\\}'` с правильным экранированием
- **Статус:** ✅ Решено
