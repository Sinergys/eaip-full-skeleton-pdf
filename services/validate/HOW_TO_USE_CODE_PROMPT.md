# 📖 Как использовать Claude Code для Phase 2

## 🎯 Цель

Передать детальный промпт из `CLAUDE_CODE_PROMPT_PHASE2.md` в Claude Code для реализации полной функциональности Word Validator.

---

## 📋 Пошаговая инструкция

### Шаг 1: Открыть Claude Code

1. Открой терминал в директории проекта
2. Запусти Claude Code:
   ```bash
   claude-code
   ```

### Шаг 2: Скопировать промпт

1. Открой файл: `CLAUDE_CODE_PROMPT_PHASE2.md`
2. Скопируй **ВЕСЬ** контент файла (Ctrl+A, Ctrl+C)

### Шаг 3: Передать промпт в Code

**Вариант A - Прямая передача:**
```
Вставь скопированный текст в Claude Code и отправь
```

**Вариант B - Поэтапная передача (рекомендуется):**

**Сообщение 1:**
```
Привет! Я передаю тебе техническое задание для реализации Phase 2 модуля Word Document Validator.

Это часть проекта EAIP - автоматизация энергоаудита в Узбекистане.

Phase 1 (базовая инфраструктура) уже завершена мной. Твоя задача - реализовать 4 ключевых модуля:
1. DocxProcessor - извлечение контента из DOCX
2. AIProcessor - интеграция с Ollama и DeepSeek
3. DocumentAssembler - сборка финального документа
4. OrchestratorService - полный pipeline

Сейчас я передам тебе детальное ТЗ. Готов?
```

**Сообщение 2:**
```
[Вставь содержимое CLAUDE_CODE_PROMPT_PHASE2.md целиком]

Начни с реализации OrchestratorService и DocxProcessor - это самые критичные модули.
```

### Шаг 4: Мониторинг процесса

Claude Code будет последовательно создавать файлы. Следи за:

1. **Созданием файлов:**
   - `services/docx_processor.py`
   - `services/ai_processor.py`
   - `services/document_assembler.py`
   - Обновлением `services/orchestrator.py`
   - Обновлением `db/cache.py`

2. **Тестами:**
   - Code может создать тестовые файлы
   - Запусти их для проверки

3. **Ошибками:**
   - Если Code сообщает об ошибке - дай feedback
   - Укажи на проблемные места

### Шаг 5: Валидация результата

После завершения реализации:

**Проверь чеклист из промпта:**
```bash
# Запусти тестовый файл
python test_word_validator.py

# Проверь endpoint
curl -X POST "http://localhost:8003/api/v1/check-report/" \
  -F "file=@test.docx"
```

**Ожидаемый результат:**
- ✅ Файл обрабатывается без ошибок
- ✅ Создаётся файл `*_Проверенный.docx`
- ✅ В файле есть исправленный текст
- ✅ В файле есть секция с рекомендациями
- ✅ Кеш работает (второй запрос быстрее)

## 🔧 Если что-то пошло не так

### Проблема: Code не понимает структуру проекта

**Решение:**
```
Code, структура проекта следующая:

C:\eaip\eaip_full_skeleton\services\validate\
├── services/      # Сюда создавай новые модули
├── core/          # Уже готово
├── db/            # Доработай cache.py
└── api/           # Уже готово

Базовая директория для работы:
C:\eaip\eaip_full_skeleton\services\validate
```

### Проблема: Ошибки импорта

**Решение:**
```
Code, используй относительные импорты:

from ..core.config import settings
from ..core.models import ExtractedObject
from ..utils.exceptions import ProcessingError

НЕ используй абсолютные импорты вроде:
from validate.core.config import settings  # ❌ Неправильно
```

### Проблема: Code создаёт слишком много файлов

**Решение:**
```
Code, пожалуйста, создавай файлы по приоритетам:

Первая итерация:
1. services/orchestrator.py (полная реализация)
2. services/docx_processor.py

Вторая итерация:
3. services/ai_processor.py
4. services/document_assembler.py

Третья итерация:
5. db/cache.py (доработка)
6. Тесты
```

### Проблема: Code делает ошибки в реализации

**Дай конкретный feedback:**
```
Code, в файле services/docx_processor.py в методе extract_content():

Ошибка в строке 45:
    document = Document(file_path)  # ❌

Должно быть:
    from docx import Document
    document = Document(file_path)  # ✅

Пожалуйста, исправь.
```
