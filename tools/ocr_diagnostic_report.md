## 3. ТЕСТ КЕЙС ДЛЯ fix_string_content()

**Проблемные входные строки:**

1. ✅ **Успешно:** `'Текст с\nпереносами строк'`
   - Обрабатывается корректно: `\n` экранируется в `\\n`

2. ✅ **Успешно:** `'Смешанный\tтекст\nс табуляцией'`
   - Обрабатывается корректно: `\t` и `\n` экранируются

3. ❌ **ОШИБКА:** `'Строка с "кавычками" и\nпереносами'`
   - **Проблема:** Кавычки внутри строки ломают JSON парсинг
   - **Ошибка:** `Expecting ',' delimiter: line 1 column 21`
   - **Причина:** Регулярное выражение `r'"([^"]*(?:\\.[^"]*)*)"'` не обрабатывает вложенные кавычки корректно

4. ✅ **Успешно:** `'Unicode: \u00A0\u2009\u202F'`
   - Unicode символы обрабатываются корректно

5. ✅ **Успешно:** `'Control: \x00\x01\x02'`
   - Управляющие символы удаляются корректно

**Паттерны, которые могут вызвать проблемы:**
- Вложенные кавычки в строках: `"текст с "кавычками" внутри"`
- Экранированные обратные слэши: `"путь\\к\\файлу"`
- Многострочные строки с кавычками
- Unicode escape последовательности: `\uXXXX`

**Требуется доработка:**
- Улучшить обработку вложенных кавычек
- Добавить обработку экранированных обратных слэшей

## 5. ПАРАМЕТРЫ CONFIDENCE

**Текущие пороги (из кода):**
- **text:** Не используется явный порог (Tesseract возвращает confidence по словам, среднее ~40%)
- **numbers:** Не используется явный порог
- **dates:** Не используется явный порог
- **tables:** Не используется явный порог (определяется эвристиками)

**Фактические значения confidence из Gemini:**

| Страница | Confidence | Таблиц | Символов |
|----------|-----------|--------|----------|
| 1 | 0.9 | 1 | 2,484 |
| 2 | 0.95 | 1 | 2,350 |
| 3 | 0.95 | 1 | 1,062 |
| 4 | 0.95 | 0 | 1,244 |

**Анализ:**
- Gemini возвращает confidence в диапазоне 0.9-0.95 (высокий)
- Tesseract confidence: 38.5-46.0% (средний)
- Confidence извлекается из JSON ответа Gemini через regex: `r'"confidence"\s*:\s*([\d.]+)'`
- Если confidence отсутствует в ответе, используется fallback: `0.5`

**Рекомендации:**
- Добавить явные пороги для фильтрации низкокачественных результатов
- Рекомендуемые пороги:
  - text: > 30% (Tesseract)
  - tables: confidence > 0.7 (Gemini)
  - numbers: проверка валидности числовых паттернов

## 6. ГОТОВНОСТЬ К BATCH-ОБРАБОТКЕ

**Текущие ограничения:**

1. **Gemini API:**
   - ~18-23 сек/страница
   - Возможны таймауты (504) при больших изображениях
   - Требуется интернет-соединение
   - Может быть rate limit (не проверено)

2. **Tesseract:**
   - ~5-10 сек/страница
   - Локальная обработка, без ограничений сети
   - Память: зависит от размера изображений

3. **Память:**
   - Зависит от размера изображений (DPI 300)
   - ~10-50 МБ на страницу в памяти

4. **Сеть:**
   - Требуется для Gemini API
   - Стабильное соединение критично

**Оценка для 20-50 файлов:**

```
50 файлов × 4 страницы × 18 сек = 3,600 сек = 60 минут
```

**Рекомендации:**
- ✅ **Готовность:** Да, с ограничениями
- **Батчи:** По 5-10 файлов с паузами между запросами
- **Прогресс-бар:** Обязателен для отслеживания
- **Логирование:** Сохранять результаты каждого файла отдельно
- **Retry логика:** При таймаутах Gemini API
- **Параллелизация:** Не рекомендуется (может вызвать rate limit)

**Оптимизации:**
- Кэширование результатов для повторной обработки
- Сжатие изображений перед отправкой в Gemini (если API поддерживает)
- Локальная предобработка + Gemini только для сложных случаев
